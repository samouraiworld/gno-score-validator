# score-validator

Scoring for gno.land test13 validator candidates. A Go tool computes every
score from CSV files versioned in this repo, renders a Markdown scoreboard and
a standalone HTML scorecard, and publishes the same numbers to the **Score
Gno-Validator** Google Sheet. The repo is the source of truth; the sheet is an
output, locked against hand edits.

**Scores: [scoreboard/](scoreboard/README.md)** — the ranking and one page per
validator, generated from `data/scorecard.json` and readable right here on GitHub.

Every arena is final: the testnets (test13, topaz, sapphire, pearl) have ended
and the fire drill has closed. Mainnet (`gnoland-1`) is shown on the page and
the scoreboard but no total includes it: none of its validators is a candidate
yet, and its weight will be decided when one joins.

## The score

```
Score = ( Test13-challenge + Score-test13 + Score-topaz + Score-sapphire + Score-pearl + Fire-drill ) / 6
      + GitHub / 10,   capped at 100
```

The six arenas carry equal weight, so each contributes at most 16.7 points.
GitHub is a bonus on top worth at most 10: it can lift a candidate, never sink
one. **The cap matters** — without it the formula reaches 110.
The divisor is the number of arenas marked `in_total` in
`config/arenas.json`. `data/scorecard.json` records each arena's `1/6` weight
as the full repeating decimal available to JSON; the executable rule remains
the integer divisor above.

GitHub participation is scored as:

| Signal | Weight |
| --- | --: |
| Merged pull request | 25 |
| Unmerged pull request | 8 |
| Issue opened | 5 |
| Commit | 3 |
| Comment thread | 2 |

A merged pull request is the only artefact that proves code landed, so it
outweighs intent and discussion by a wide margin. Only contributions dated
**2025 or later** count: earlier work is real, but says nothing about
involvement in the testnet being scored.

12 of the 98 candidates could be tied to a GitHub account, each verified by
hand — see `data/github-evidence.csv` for the evidence behind every match. A
blank GitHub column is absence of evidence, not evidence of absence, and never
costs points.

## Usage

```bash
go build -o bin/scoresheet ./cmd/scoresheet
```

Offline, from `config/` and `data/` alone — no `-id`, no key:

```bash
./bin/scoresheet score -dry                    # recompute data/scorecard.json, the page and scoreboard/
./bin/scoresheet render                        # regenerate scoreboard/ and the page payload from scorecard.json
./bin/scoresheet fetch -chain gnoland-1 -dry   # live gnomonitoring report -> data/arenas/mainnet.csv
./bin/scoresheet firedrill -dry                # portal exports -> data/arenas/firedrill.csv
```

Against the sheet, which must be shared with the service account as an
**Editor**. Find its address in the key file:

```bash
python3 -c "import json;print(json.load(open('service-account.json'))['client_email'])"
```

```bash
ID=<spreadsheet-id>
./bin/scoresheet -id $ID sheet diff            # every cell where the sheet differs from the repo (read-only)
./bin/scoresheet -id $ID sheet push -dry       # write Bilan, the arena tabs and the Dashboard, then lock
./bin/scoresheet -id $ID sheet lock -dry       # protect every tab, editable by the service account only
./bin/scoresheet -id $ID freeze -dry           # copy the arena tabs and Bilan A:B back to data/
./bin/scoresheet -id $ID audit                 # numbers stored as text (read-only)
./bin/scoresheet -id $ID dump "Bilan!A1:L3"    # inspect cells (read-only)
./bin/scoresheet -id $ID export Dashboard out.pdf
```

Every command that writes to the repo or the sheet takes `-dry`. Start there.
`export` only saves a local PDF, and ignores `-dry`.

`snapshot`, `bilan`, `refresh`, `coerce` and `dashboard` are retired. Each
prints what replaces it and exits.

### Run order

After changing any input — an arena CSV, `candidates.csv`, `github-links.csv`
or `evidence.json`:

1. `score`, which also renders `scoreboard/` and re-embeds the page payload.
2. Commit `data/scorecard.json`, `scoreboard/` and the page with the input.
3. `sheet push -dry`. It lists every cell where the sheet differs from the
   repo; until the push, that is your change. If the list holds nothing else,
   `sheet push -force`. A cell you did not change is a sheet edit: `freeze`
   it into a pull request first, or discard it with `-force`.

To update mainnet: `fetch -chain gnoland-1 -dry`, the same without `-dry`,
then `score`.

### The commands

`score` rebuilds `data/scorecard.json` from the repo alone: config, candidates,
arena CSVs, GitHub links and evidence. Every join is by moniker. It refuses an
evidence block whose moniker matches no candidate, so a block cannot vanish
from the page unnoticed. The `mainnet` block is built from
`data/arenas/mainnet.csv`; only `source` and the GitHub weights are carried
over from the previous file. Equal scores share a rank. A parity test
recomputes every total from the CSVs and fails if it disagrees with
`data/scorecard.json`.

`render` builds `scoreboard/` from `data/scorecard.json` alone and re-embeds
the page's payload. Both carry public fields only. The page keeps the GitHub
login, profile link, match rule, confidence and contribution counts, and drops
Discord handles, real names, bios, blogs and the matching notes. The page
payload goes through an allowlist (`cmd/scoresheet/page.go`), so a new
evidence field stays private by default, and a test fails if the committed
page differs from it.

`fetch -chain <id>` writes a chain's live gnomonitoring report to the CSV of
the config arena with that `chain`. It prints the moniker-level diff first. It
refuses an empty report, a report that would drop more than a fifth of the
file, and any final arena, unless given `-force`. Every arena is final today;
only mainnet is expected to move. `firedrill` refuses to rewrite the fire
drill without `-force` too.

`sheet diff` compares the sheet with `data/scorecard.json` and the arena CSVs,
cell by cell — values, not formulas — and exits 1 when anything differs.

`sheet push` runs `sheet diff` first and refuses to overwrite any difference
without `-force` — including the change you are publishing, since the diff
cannot tell a repo change from a sheet edit. Read the list before forcing: a
sheet edit worth keeping goes into the repo instead (`freeze`, then a pull
request). It also refuses while `data/scorecard.json` is stale. It then
writes Bilan and every arena tab as values, rebuilds the Dashboard, leaves a
note on A1 of each tab ("Generated from the git repo — edit the CSV by pull
request"), applies `sheet lock`, and checks that a second diff is empty.

`sheet lock` protects every tab so only the service account can edit it. The
file owner keeps edit rights regardless — Sheets offers no way to lock the
owner out — which is why `sheet push` diffs before writing.

`freeze` copies every arena tab listed in `config/arenas.json` into
`data/arenas/<id>.csv`, and Bilan's moniker and Discord columns into
`data/candidates.csv`. It is the way back for an edit made in the sheet.

## What the sheet holds

**Bilan is fully generated.** Its layout follows the config:

- **A** moniker and **B** Discord, from `data/candidates.csv`
- one column per arena, in config order (C–H with six arenas)
- then GitHub participation score (restricted to the cutoff year), Score,
  GitHub login and match confidence (I–L with six arenas)

Every cell is a value, not a formula. A seventh arena shifts the last four
columns right. Change a cell by editing its CSV in a pull request, never in the
sheet.

Each arena tab is its CSV verbatim. A column is written as numbers when every
filled cell in it is a number; the moniker column never is.

The Dashboard is the one tab that keeps formulas: it reads Bilan, so its
dropdown and charts stay live. `sheet push` clears its cells, charts, banding
and conditional rules before rebuilding, so repeated runs do not stack
duplicates.

The `Github` tab is locked but neither diffed nor written: no repo file has
its layout.

## The monitoring reports

The metrics behind the four network tabs come from gnomonitoring. Only
**sapphire-1** and **pearl-1** are still served: `topaz-1` returns the two
remaining core validators and `test13` is a `400 invalid chain ID`, so the CSVs
under `gno-monitoring-metrics/` are frozen backups for those two chains and the
only record left of what they held.

`score` joins every arena to the candidates by **moniker**, not by address,
and case-insensitively (`scoring.Key`). That matters more than it
looks: between the 18/08 snapshot and the live report only 17 sapphire
addresses out of 86 survived, 24 monikers having rotated to a new address. A
join on the address column would have dropped three quarters of the rows.

A moniker absent from an arena's CSV scores zero there. That is a scoring
decision, not an accident: leaving the active set costs the whole sapphire
contribution of 16.7 points.

## fr_FR, and four ways it breaks formulas

The spreadsheet's locale is French. Each of these produced a silent wrong
answer before it was pinned down. They still matter for the Dashboard's
formulas and for every value `sheet push` writes, and all four are handled in
`internal/sheetx` or by `sheet push`:

1. **The argument separator is `;`, not `,`.** Formulas are parsed in the
   sheet's locale, so a comma-separated formula lands as `#ERROR!` on every
   row. Function names, however, may stay English — both `MEDIAN` and
   `MEDIANE` work.
2. **Array literals separate columns with `\`.** `SPARKLINE`'s options array is
   the usual victim.
3. **A tab name containing a hyphen must be quoted.** `Score-test13!E2` parses
   as the subtraction `Score` minus `test13!E2` and returns a plausible-looking
   wrong number rather than an error. Always go through `sheetx.Ref`.

4. **A `.` decimal can be read as a date.** `12.6` imported into the proposer
   column landed as the 12th of June, storing the serial 46185 where a
   percentage belonged — on 50 of 53 rows. `audit` cannot see it, because a
   date *is* a number. `sheet push` sidesteps it by sending JSON numbers under
   `RAW` and resetting the number format, since a cell still carrying
   the date format would render a good value as a bad date.

Weights are written as fractions (`/6`, `/10`) rather than decimal multipliers, so
the decimal separator never enters a formula at all.

A related trap: values imported with a `.` decimal separator, and bonuses
written `"+0.50"`, were once stored as **text**. `SUM` and `AVERAGE` skip text
silently, so those columns averaged to zero without any warning. `sheet push`
writes JSON numbers, never text, which sidesteps locale parsing entirely;
`audit` still reports the condition.

## The HTML scorecard

`web/validator-scorecard.html` is self-contained — open it in a browser, no
server and no network. It carries the same scorecard the sheet does: overall
standings, a per-validator profile with the on-chain detail for all four
networks, one page per scoring arena, and the GitHub evidence.

Run `score` after any change to an input CSV, or the page keeps serving the
previous run's numbers.

It rounds half away from zero to match Google Sheets. Plain `toFixed` rounds on
the binary representation, which renders the median as 59.42 against the
sheet's 59,43.
